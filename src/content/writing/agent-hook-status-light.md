把任务交给 Agent 之后，我们常常会进入一种奇怪的等待：它是在读文件、调工具、思考，还是已经卡住了？于是人还在做别的事，眼睛却总忍不住回到对话框，看看那一行“正在处理”有没有变化。

我想解决的，正是这件小事。

我做了一个 macOS 本地桌宠：**TrafficLightController**。它像一个悬浮在桌面的红绿灯，不必盯着聊天窗口，也能知道 Agent 的状态：

- 红灯：空闲，等待下一条任务；
- 橙灯闪烁：正在工作；
- 绿灯：任务完成，结果等你来看。

![不用盯屏，也能知道 Agent 在做什么](/images/writing/articles/agent-hook-status-light/01.webp)

这不是为了给桌面增加一个可爱的摆件。真正有价值的，是它把 Agent 原本藏在对话框里的运行过程，变成了一个可以被余光捕捉的信号。

人不需要一直守在屏幕前。橙灯亮着，就继续做自己的事；绿灯亮起，再回来查看结果。对于会运行几分钟、会反复调用工具的任务，这种“知道它还活着”的感觉，比一段静态加载文案可靠得多。

## 红绿灯背后，不是提示词，而是 Hook

最初，我也可以要求 Agent 在开始和结束时自己调用一个命令。但这不可靠：模型会忘，网络会重连，长时间思考时也未必有工具调用。

所以，状态灯接入的是 Agent 的真实生命周期：任务开始时发出 `start`，执行过程中持续 `heartbeat`，完成时 `done`。对于支持原生 Hook 的宿主，这些事件由宿主发出，而不是依赖模型“记得去做”。

![Hook 把开始、心跳与完成接到同一条线上](/images/writing/articles/agent-hook-status-light/02.webp)

这也是我重新理解 Hook 的地方：它不只是“在某个时机跑一段脚本”。它是一条把 Agent 内部事件接到外部世界的接口。

有了这条接口，状态灯只是第一个很直观的应用。任务开始、工具调用前后、权限请求、任务取消、会话结束，都可以成为治理的触发点：

- 在危险操作前加一层审批；
- 为工具调用留下可追溯记录；
- 在预算、重试或长时间无心跳时提醒人；
- 在 Agent 无法继续时，把任务明确交还给人；
- 在多 Agent 协作中，让任务状态不再是黑盒。

![从状态可见，到边界、追溯与接管](/images/writing/articles/agent-hook-status-light/03.webp)

这套思路可以继续长成一个轻量的 Agent 治理框架：**生命周期负责感知，策略负责边界，日志负责追溯，人负责最终接管。** 红绿灯很小，却是这个框架最容易被感受到的入口。

## 现在就可以体验

TrafficLightController 已在 GitHub 开源，支持 Codex、WorkBuddy、Claude Code、Hermes、MCP Agent 与本地宿主接入方式。源码、安装说明和 Hook 配置都在这里：

**GitHub：<https://github.com/Kz-Aven/TrafficLightController>**

如果你在使用 WorkBuddy，也可以直接到技能板块搜索：**“桌宠红绿灯”**，完成安装后就能在桌面上看到 Agent 的工作状态。

一个小灯解决不了 Agent 的全部问题，但它让“它现在在做什么”不再只能靠猜。这也许正是构建可靠 Agent 的第一步：先让过程变得可见。
