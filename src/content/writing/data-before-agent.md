> 前段时间，应朋友之邀，下厂里做了工厂 AI 落地项目。两套视角记录：【我在工厂做 AI】面向业务，讲工厂实际难题；【制造工厂实践 AI】面向产品，拆解方案底层取舍，全部来自一线真实复盘。

帮朋友的工厂做 AI 落地之前，我以为自己需要花最多时间的地方，是怎么把智能表格、Agent 和企业微信连接起来。

这部分我以前做过不少。之前参与制造业的项目，企业往往已经有相对完整的系统和数据接口，我做的更多是把不同系统的数据接入 Agent，给它业务上下文，再把数字员工嵌进具体流程，辅助人工作，或者接手一些重复劳动。

这次的目标也很明确：帮朋友刘总把工厂的成品库存管理做起来。

刚开始，我很快搭通了一条测试链路：企业微信群里报工，机器人把信息交给 WorkBuddy，处理之后写进智能表格。测试跑通的时候，我还觉得挺顺。

然后，我开始研究怎么让 AI 匹配产品、处理库存数据，事情就卡住了。

不是连接没搭好，而是面对客户料号、车间产品名称和旧系统编码，我自己都不敢确定它们是不是对应同一个产品；AI 匹配出一个结果，我也不知道该拿什么去核验。

于是我先停下手头的流程搭建，和刘总一起回去梳理数据。

这次经历对我做 AI 产品的触动挺大：进入一个业务现场，先要弄清楚数据在哪里、经验在哪里，再决定 Agent 应该怎么获取上下文。具体要做到什么程度，也要看企业现有的基础，不能预设所有数据都已经整理好，等着我们来调用。

## 先别急着问“能做什么 Agent”

刘总的工厂是一家小型注塑加工厂，主要生产电源适配器、转换插座的塑胶外壳。工厂原本有一套旧系统，也有不少 Excel，并不是完全没有数据。

他最头痛的事情是成品库存：车间里说的产品名称，和旧系统里的料号对不上；想看现在有什么货，需要把系统数据导出来，再和几份 Excel 查找、比对。

我到厂里之后，还看到车间领班手写的工作日报、办公室收集的纸质单据，以及桌上堆着的其他业务资料。刘总平时安排工作、听员工汇报，很多时候靠电话；产品之间的对应关系，他自己也记得很清楚。

如果从产品方案开始想，很容易先列出一串能力：库存查询、生产统计、订单分析、自动报工……这些都可能有价值，但我后来觉得，进场时先抓住一件具体的事会更有用。

这次我们抓的是“查清成品库存”。沿着这件事往下走，再去找：产品是怎么称呼的，入库记录在哪里，出库单据在哪里，现有库存又是怎么统计出来的。

这样做的原因很简单：范围越具体，越容易找到真实发生过的一笔业务，也越容易发现数据断在哪。先把一个产品从入库、出库到库存的链路看明白，比一开始画一张覆盖全厂的系统架构图，更容易判断下一步要做什么。

## 数据盘点：找到文件还不够，还要知道它能回答什么

我请刘总把能找到的资料都拿出来，包括旧系统的数据、Excel、PDF、客户采购单、仓库送货单，以及车间的工作日报和巡检记录。

第一眼看过去，我的感觉就是乱：文件多，一个 Excel 里面还有很多工作表，产品在不同资料里使用的名称也不一样。

对于产品经理来说，盘点这类资料时，可以先围绕那条具体业务，把每份资料的用途记下来：

| 要弄清楚的问题 | 可以从哪里找 | 还需要确认什么 |
| --- | --- | --- |
| 客户订的是什么产品 | 客户采购单、客户料号资料 | 这个客户料号对应厂内哪个产品 |
| 厂里生产的是什么 | 产品资料、车间日报 | 车间名称与厂内料号是否对应 |
| 已经送出了多少 | 送货单、出库记录 | 单据是否完整，记录是否已更新 |
| 现在还有多少库存 | 旧系统、库存表、出入库记录 | 各份数据的时间范围和产品口径是否一致 |

这张表是我基于项目经验整理出的盘点方式，不是说每家工厂都恰好有这些资料。实际操作时，还可以给每份资料记上维护人、更新时间和疑点；没有的内容就先标出来，别急着当成零。

为什么要多记这些？因为“找到了一个库存数字”和“知道这个数字能不能用于今天的查询”，是两件事。比如一张表里的产品名称和另一张表里的编码没有确认关系，两个数字即使看起来很像，也不能直接认定它们可以相加或比较。

## 找到业务经验的拥有者，让他能参与确认

在这家工厂，很多产品对应关系都在刘总脑子里。给他一个客户料号，他大多能说出对应厂里的什么产品；有的产品名称只差一点，他也知道实际区别在哪里。

因此，做数据盘点的时候，除了问“数据在哪里”，我还会特别关注：谁能判断这条数据对不对？遇到两个资料说法不一致，最后请谁确认？

在这个项目里，这个人主要是刘总。他之前已经制定过一份物料编码规则，只是还没有把产品编码统一起来。我们先把规则梳理好，让 AI 根据规则做第一轮加工；我帮忙查重、列出待核对的项，再交给刘总确认和修正。

刚开始，AI 比较保守，把很多数据都标成待核验。我们后来调整了方式：规则明确、信息充分的部分先处理，刘总随机抽查；编码重复、颜色或者设备信息不明确的，再列出来逐项确认。大约四分之一的数据需要进一步核对，这是当时的估计。

这里有个很实际的分工：AI 适合按已有规则处理大量资料、帮忙发现重复和疑点；真实产品之间到底是什么关系，还是要找了解业务的人确认。刘总抽查时暂时没有发现错误，但这不等于所有数据都已经逐条验证过。

对实施者来说，让业务负责人参与，不一定意味着让他从头看完每个文件。可以先把待确认的问题整理成清单，带上原始名称、来源和疑点，让他能快速判断；确认后再把结果写回统一的基础资料里。这样既用上业务经验，也尽量减少重复核对。

## 给同一个产品建立可追溯的对应关系

库存要算得清楚，首先得能识别产品。

举个例子：车间说“电源外壳下盖”，客户采购单上用客户自己的料号，厂里又有自己的产品料号。系统不能只因为名称看着相似，就认为它们一定是同一件东西。

我们最后整理了几类基础资料：厂内产品主表、客户料号表、客户料号和厂内产品的关系表、客户表。各自解决不同问题：产品叫什么、客户怎么叫、两边怎么对应，以及客户是谁。

实际处理一笔业务时，可以沿着客户和客户料号找到对应关系，再找到厂内产品，后续入库、出库和库存都尽量关联到明确的产品记录。匹配不到或者对应了多个厂内产品时，就不能悄悄选一个结果继续往下跑，而要留下线索，让人核对。

尤其是一对多：一个客户料号在少数情况下会对应上盖、下盖等多个厂内产品。我们原本希望全自动处理，但当时智能表格的自动化能力和实际配置限制，让这部分处理起来比较麻烦；最后由常见的一对一情况走自动化，少数多料号情况交给人工复核和拆分。

这里的经验是先把业务关系表达清楚，再决定工具能自动做到哪一步。为了避免误扣库存，待复核记录也要能看出是哪张订单、哪个客户料号或涉及哪些候选产品，不能只留一句“请核对”。

## 把现场操作约束一起放进方案

数据和关系梳理好之后，还得回到现场看人怎么用。一个设计在流程图上走得通，到了车间或仓库，不一定就顺手。

我们当时试过群报工链路，测试是通的；后来员工日常使用的方式，是在企业微信里主要填写产品料号和数量，其他信息由系统带出。对车间来说，能快速完成录入，比知道背后用了什么 Agent 更重要。

送货单也一样。我最初想让员工录完出库记录后，由 Agent 回填送货单并调用打印机。但送货单需要尽快打出来给司机，等待 Agent 处理可能比较慢，稳定性也有顾虑。

和刘总讨论后，我们保留先填写、打印送货单的做法，再把文件保存到指定文件夹，让 WorkBuddy 定时读取并录入出库台账；缺失信息由人补充。这个流程已经在用，目前每小时读取一次。

这样设计有明确代价：送货发生后到台账同步之前，库存可能暂时没有反映这次出库。刘总结合当前业务量，认为这个时间差可以接受。对实施者来说，这个约束需要写清楚；如果换成出货频繁、必须实时控库存的场景，就需要重新评估同步方式。

我现在会把现场约束和数据一起盘点：操作人是谁，什么动作必须马上完成，哪些信息能自动带出，出现疑点时谁来处理，以及查询结果需要多及时。这些问题会直接改变流程设计。

## 先用一条真实业务，把链路核对通

基础资料和流程有了之后，不要只看自动化日志上是不是显示“运行成功”，还要回到业务数据本身。

我建议选一条能追溯的真实业务，或者经过明确标记的测试业务，从头核对：客户料号能否找到正确产品，入库和出库有没有落到对应产品，库存计算使用的是什么数据，异常时是否有人能看懂并处理。

例如，一个订单对应多个厂内产品时，不能只检查“生成了一条待核对记录”；还要看记录里有没有足够的信息让人知道核对什么，以及人工拆分之后能否关联回订单和对应产品。

同样，定时同步送货单的场景，除了看任务是否执行，也要对照文件和台账核对内容是否完整，并留意同步时间差。重复导入、失败重试和告警等机制，需要结合实际配置单独检查，不能因为一次成功就认为都已经解决。

这也是为什么我会把“流程运行了”和“业务结果对得上”分开看。前者告诉我们工具执行了动作，后者才帮助我们判断，这个流程能不能支撑日常工作。

## Agent 的工作，仍然是连接业务上下文

权威数据准备好之后，我大约用了两个下午搭建业务流程；但前面梳理、核对数据，尤其刘总为了关系表熬的几个通宵，不能算作不存在。

现在，成品出入库、订单和生产计划流程已经在使用；刘总也能用 WorkBuddy 查询日常出库情况。历史数据还没有全部录入，他希望进一步了解的产能、排产和真实成本，仍需要更多数据积累，不能说已经实现。

回头看，这次和我以前做的 Agent 项目，底层思路其实是相通的：都是找到业务需要的上下文，让工具在合适的环节发挥作用。区别在于，以前不少上下文已经存在系统和接口里；这一次，我们先要和业务负责人一起，把分散在旧系统、表格、纸张和经验里的信息整理出来。

所以，产品经理进场之后，我觉得可以先沿着一件具体业务走一遍：找到数据来源，找到能确认数据的人，弄清楚产品或订单怎么对应，再看员工实际怎么操作。等这些问题有了答案，再去决定用什么表、怎么连接 Agent、哪些地方自动化，方案会更贴近现场。

下一篇，我想具体聊聊那份产品资料是怎么清洗的：当 AI 把很多结果都标成“待核验”，我们又是怎么重新划分 AI 和人工的工作。
