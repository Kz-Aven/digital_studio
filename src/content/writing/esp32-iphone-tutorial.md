上一篇，我讲了怎么给 Agent 接上“眼睛”和“手”。这篇把过程拆开：从买板子、选数据线，到连接手机、校准指针，再把控制能力接进 MCP。

我实际用的是 ESP32-S3-DevKitC-1-N16R8、一台 M4 Mac，以及一部 Lightning 接口、运行 iOS 16.7.16 的 iPhone。

最后跑通的任务，包括打开微信、按上下文回复消息，以及给朋友圈内容点赞。

先看实际连接和操作效果：

[▶ 观看原始演示视频](/media/writing/esp32-to-iphone.mp4)

手机无需越狱，无需安装测试 App，也不用准备 Apple 开发者账号。但电脑需要持续运行服务，手机也要保持解锁。

这篇不展开终端命令和代码。你可以先按下面的顺序理解、检查每个环节，具体安装命令和脚本都放在文末的开源仓库里。

## 先看全流程：不要一上来就让它回微信

我建议按这条顺序复现：

![从物料准备到微信任务验证的八步实操流程图](/images/writing/articles/esp32-iphone-tutorial/01.webp)

这里有两条连接，后面排错时要分开看：

**手机画面经 AirPlay 传到电脑，Agent 才能看见屏幕。**

**电脑经 Wi-Fi 给 ESP32 发指令，ESP32 再通过 USB 模拟鼠标和键盘，手机才会响应操作。**

所以，电脑看到了手机画面，不代表鼠标一定能动；板子在线，也不代表手机画面已经传过来了。

![Tiro 接通画面回传与动作控制两条独立链路](/images/writing/articles/esp32-iphone-tutorial/02.webp)

## 第一步：准备物料，把线买对

如果你已经有手机、电脑和 Wi-Fi，核心新增硬件就是一块板子，加一套能连接手机的数据线或适配器。

我这次的配置如下：

| 物料 | 数量 | 选购或使用要点 |
|---|---:|---|
| ESP32-S3 开发板 | 1 块 | 实测型号为 ESP32-S3-DevKitC-1-N16R8；需要能使用芯片的原生 USB |
| Lightning OTG 数据连接 | 1 套 | 实测使用 Micro-USB 转 Lightning OTG 线；接口要与你的板子匹配，并确认支持数据和 USB 主机模式 |
| 电脑连接板子的数据线 | 1 根 | 首次烧录接 UART；已有合适的数据线可以复用 |
| iPhone | 1 部 | 本次实测为 Lightning 接口、iOS 16.7.16 |
| 电脑 | 1 台 | 本次实测为 M4 Mac，负责运行服务和 Agent |
| Wi-Fi 路由器 | 已有即可 | ESP32 要能连接 2.4GHz 网络，电脑和手机之间不能被网络隔离 |

基础控制不需要额外购买麦克风、扬声器、显示屏、电阻或 LED。成本主要在开发板和兼容的数据连接上。

![Tiro 从工具包取出 ESP32 和兼容数据线](/images/writing/articles/esp32-iphone-tutorial/03.webp)

不过，“一条数据线”不能只看两端插头能不能插进去。

我最开始用过一拖三充电线。板子能亮灯，电脑却识别不到设备，排查了好几轮才发现，数据传输这一步根本没打通。

**灯亮，只能证明有电。**

普通充电线不一定能传数据，能传数据的线也不一定能让 Lightning iPhone 作为 USB 主机使用。买之前要分别确认这两件事。

如果你用 USB-C iPhone，或者换了另一种开发板，线材和供电组合需要重新验证，不能直接把这次 Lightning 的结果套过去。

## 第二步：板子先接电脑，确认它真的被识别

拿到板子后，先不要接手机。

查看板上两个 USB 接口旁的标识。对我这块板子来说，一个用于 UART 串口烧录，另一个是芯片原生 USB，后面用来连接 iPhone。

两者的用途要分清：

| 当前要做什么 | 接哪个接口 |
|---|---|
| 给 ESP32 写入固件、查看串口输出 | UART 接电脑 |
| 让 ESP32 模拟鼠标键盘操作手机 | 原生 USB 接 iPhone |

![Tiro 分清 UART 烧录与原生 USB 运行接口](/images/writing/articles/esp32-iphone-tutorial/04.webp)

*接口用途示意，具体接口形状以实物为准。*

先把 UART 接到 Mac，检查系统是否出现对应串口设备。

如果只有灯亮，没有串口，优先排查数据线、USB 接口和扩展坞。没有看到串口，就还没到排查固件或模型的时候。

还要注意一个容易误判的地方：扩展坞能用 HDMI 投屏，并不能证明它的 USB 数据口或当前这根线正常。最好用 U 盘、鼠标或已知能传数据的设备，测试同一个 USB 口。

这一关的完成标志是：**电脑能识别板子的串口，而不只是板子通电。**

## 第三步：准备电脑环境，先让基础服务跑起来

电脑端主要需要三类工具：

| 工具 | 负责什么 |
|---|---|
| Arduino CLI 与 ESP32 开发板支持包 | 编译固件、把程序烧录进 ESP32 |
| Python 运行环境与项目依赖 | 运行控制服务和 MCP 工具 |
| UxPlay 与 GStreamer | 接收 iPhone 的 AirPlay 镜像，转换成可供 Agent 读取的画面 |

开源仓库已经提供环境准备脚本和安装说明。按仓库里的 macOS 路径安装即可，不用从头拼装依赖。

如果你习惯让编程 Agent 协助安装，可以把仓库交给它，并明确要求：

> 按仓库文档配置本地环境，先验证服务和设备连接。涉及插拔数据线、按开发板按钮、开启手机设置时，再告诉我需要做什么。

这里暂时不需要给项目额外填写视觉模型的密钥。

我早期联调时单独接过模型做测试；后来把能力抽成 MCP，就可以直接使用宿主 Agent 自己的视觉模型。复现当前开源版本，优先走 MCP 这条路径。

这一关的完成标志是：**电脑端服务能够启动，浏览器能打开项目控制页面。** 此时页面还没有手机画面是正常的，后面才连接镜像。

## 第四步：填写 Wi-Fi 信息，把固件烧进板子

ESP32 要知道自己连接哪个 Wi-Fi，以及连接哪台电脑来接收控制指令。

你需要在仓库的硬件配置模板中填写三项信息：

- 2.4GHz Wi-Fi 名称。
- Wi-Fi 密码。
- 运行服务的电脑局域网 IP。

第三项特别容易填错。这里要填路由器分配给电脑的局域网地址，不能填代表“设备自己”的本机回环地址。

Mac 可以在当前 Wi-Fi 的网络详情里查看 IP。建议给电脑设置路由器 DHCP 地址保留，避免换一次网络或重连后，板子还在找旧地址。

填好配置后，保持 UART 接电脑，按仓库提供的 N16R8 烧录流程编译、上传。

仓库中的默认参数对应我这块 16MB Flash、8MB OPI PSRAM 的开发板。用其他板型时，要先核对容量和 USB 配置，不要直接照搬。

这一关看两个结果：**固件上传完成；电脑服务随后能够看到板子的 Wi-Fi 连接。**

如果上传成功但板子不在线，就回头检查网络名称、密码、电脑 IP 和防火墙，不要急着换模型。

## 第五步：换接手机，先确认圆形指针出现

现在可以把板子从电脑的烧录连接中断开，用兼容的 OTG 数据连接，把 iPhone 接到板子的原生 USB 口。

注意，这一步不接 UART。

在 iPhone 打开：**设置 → 辅助功能 → 触控 → 辅助触控**。

保持手机解锁，观察屏幕上是否出现圆形鼠标指针。它说明手机已经把板子当成鼠标类外设接收了。

但看到圆点，只能证明 USB 外设这部分有进展，还不能直接宣布整套系统跑通。接下来还要确认电脑能控制它移动。

我在这一步遇到过“此配件耗电量太大”的提示，手机显示的设备名是 HID Bridge。

后来联调使用了降低功耗的固件配置，才继续跑通联网控制。这是我这组设备上的结果，不代表所有 Lightning 线和适配器都能直接由手机稳定供电。

如果你也遇到耗电提示，先查 OTG 适配器、数据线和供电组合，必要时使用支持外部供电的兼容适配器。不能只改一个软件申报值，就认为实际电流问题已经解决。

这一关的完成标志是：**手机识别外设，能看到圆形指针，没有持续阻止连接的提示。**

## 第六步：接通屏幕镜像，再校准指针

到这里，手机可能已经能接收鼠标键盘输入，但 Agent 还缺画面。

在 iPhone 控制中心打开“屏幕镜像”，选择电脑上运行的项目接收器。

当前开源版本默认名称是 **ESP32 to iPhone**。我前面联调时使用过 iPhone Agent 这个名称，两者是接收器的命名差异；复现时以你当前服务显示的名称为准。

连接后，回到电脑控制页面，检查是否出现手机实时画面。可以在手机切换一次页面，确认电脑上的画面也跟着变化。

随后执行页面中的指针校准。

为什么不能省掉这一步？因为鼠标移动是相对位移，iOS 还有指针加速。“让鼠标往右走一点”，不天然等于“落在目标按钮的中心”。

项目会尝试自动校准；如果自动校准没完成，再按页面提示，根据镜像里的实际指针位置手动完成。

我就是在完成校准后，才继续验证电脑控制手机。先观察指针能否到达目标位置，再尝试点击，排错会清楚很多。

这一关结束时，至少要确认三件事：

1. 控制页面显示开发板在线。
2. 电脑确实收到手机画面。
3. 指针能够按指令明显移动，校准已完成。

![Tiro 先校准指针并移到目标，再执行点击](/images/writing/articles/esp32-iphone-tutorial/05.webp)

**后面微信任务是否顺利，很大程度上取决于这三件事有没有扎实做完。**

## 第七步：把 MCP 接进 Agent，先做一次“只移动”测试

接下来才安装 MCP。

仓库提供了 Codex 的安装方式，也提供了其他 MCP 客户端可以参考的配置。这里的基本要求是：客户端支持本地 MCP 工具，并且能够把返回的截图交给视觉模型。

电脑端服务需要继续运行。把 MCP 加入 Agent，不等于它会自动替你启动整套硬件和镜像服务。

配置完成后，先让 Agent 做一个小测试：

> 检查开发板、屏幕镜像和校准状态。读取当前截图，只把指针移到屏幕中央，核对位置后停止，不要点击。

为什么第一条指令不直接写“帮我回复微信”？如果这时点击失败，到底是模型看错、坐标没校准，还是 USB 已经休眠，就很难分辨。

“只移动”测试把范围缩小了：有图、有连接、有校准，且电脑发出的指令确实让手机上的指针移动到了目标附近。

这一步通过，再让 Agent 打开一个 App，并在进入后停止。小任务连续成功，才继续增加输入和发送动作。

这一关的完成标志是：**Agent 通过 MCP 读到截图，执行了指针移动，并根据返回结果确认位置。**

## 第八步：从微信草稿，逐步做到回复和点赞

这套链路跑通后，再开始业务任务。

我建议把微信验证拆成三轮。

### 第一轮：打开微信，找到正确会话

让 Agent 打开微信，读取未读聊天，进入其中一个会话后停止。

先看它有没有进对人，再看它能不能理解上下文。不要在收件人还没核对时就开始输入。

### 第二轮：输入中文，先停在草稿

我这套实现的中文输入，走的是手机自己的拼音输入法。

Agent 输入拼音，读取候选区，选择正确的中文，再核对输入框里的完整文字。

这不是直接把一整段中文塞进手机。姓名、多音字和长句都可能需要修正，所以输入和发送要分开。

你可以先给它这样的任务：

> 根据当前聊天上下文拟一条自然回复，输入到草稿框，核对文字后停止，不发送。

看到草稿里的中文确实正确，再继续验证发送。

### 第三轮：允许发送，并核对实际结果

确认发送范围和回复要求后，再让 Agent 执行发送，并查看聊天里是否出现正确的已发送消息气泡。

我实际联调时，还遇到了对方要求转账的消息。这也提醒我：批量回复前，需要把任务边界说清楚，例如涉及付款、承诺或不确定的信息时先停下来。

“回复所有未读”是业务要求，不能理解成给每个新出现的请求都自动执行。

微信回复验证完成后，可以再试朋友圈：打开朋友圈，识别最新几条内容，给尚未点赞的内容点赞，最后核对状态并汇报实际完成数量。

已点赞的内容不能再随手点一次，否则可能变成取消点赞。

## 每一步都要验证，会不会多截很多张图？

这是我把项目做成 MCP 之后，专门梳理过的一点。

现在正常连续操作的方式，是**复用动作后返回的那张截图**：它既用来检查上一步有没有做对，也用来决定下一步做什么。

![同一张操作后截图用于验证上一步并决定下一步的流程图](/images/writing/articles/esp32-iphone-tutorial/06.webp)

例如，从聊天列表点进会话，返回的聊天截图就同时回答两个问题：是不是进对了人？这条消息该怎么回复？

不需要为了验证，再额外截一张相同的图。

不过，点击前仍有本地指针校验。它不调用模型，但会等待视频帧、识别指针和纠正位置，所以整套系统的速度仍然是逐步操作的节奏。

消息发出去后，也不能因为设备回了一句“收到指令”，就认定已经发送成功。还是要看实际画面。

![Tiro 用同一张截图核对上一步并决定下一步](/images/writing/articles/esp32-iphone-tutorial/07.webp)

## 我踩过的几个坑，按这个顺序排查

如果中途卡住，先判断断在哪一段，而不是把整套环境全部重装。

| 现象 | 优先排查 |
|---|---|
| 板子灯亮，电脑没有串口 | 数据线是否支持传输，是否接 UART，扩展坞同一个 USB 口是否正常 |
| 固件上传成功，服务看不到板子 | 2.4GHz Wi-Fi、密码、电脑局域网 IP、防火墙和网络隔离 |
| 镜像正常，但指针不动 | 原生 USB 接口、辅助触控、手机解锁状态；必要时重新插拔 OTG |
| 手机显示已连接镜像，电脑却没有画面 | 停止镜像后重新连接，确认真的有视频帧；仍不行再检查接收服务 |
| 指针到处偏，点击被拒绝 | 先重新观察和校准，不要关闭校验后盲点 |
| 中文停在拼音，或选词不对 | 检查拼音键盘、候选区和选词结果，先修正草稿再发送 |
| 指针闲置一段时间后消失 | 可能只是自动隐藏；先测试移动，不能仅凭圆点消失判断断线 |

还有一个换环境时容易忘记的问题：**换 Wi-Fi 后，通常要重新配置并烧录。**

当前固件把 Wi-Fi 名称、密码和电脑地址写在程序里。其中任意一项变了，板子就可能找不到原来的服务。三项都保持一致，才不需要重刷。

重启电脑服务后，也要记得重新连接屏幕镜像。手机上显示的连接状态，最后仍要用电脑端收到的实际画面来核对。

## 跑通之后，你应该得到什么

复现成功的结果，不只是板子会亮灯，或手机上出现一个圆点。

你应该能让 Agent 读取当前屏幕，移动并定位指针，打开正确的 App，完成中文输入，再通过操作后的画面核对结果。

微信回复和朋友圈点赞，是我已经走通的具体任务。换到别的 App，可以沿着同样的方法继续尝试，但效果仍受模型、界面、机型和系统权限影响。

它不会绕过手机密码、生物识别或支付确认，也不能保证所有界面都能通过镜像读取。

对第一次复现的人，我最建议坚持的是：**先把连接、画面和指针逐项验收，再把任务一点点加长。**

**GitHub：[Kz-Aven / esp32-to-iphone](https://github.com/Kz-Aven/esp32-to-iphone)**

按 README 的快速开始执行；需要核对某个步骤时，再看仓库里的搭建指南和 MCP 使用指引。从“只移动一次指针”开始，就能一步步走到真实的手机任务。
