---

这两年，Agent 的进步几乎全部来自同一件事：**模型变强了。**

推理更稳、上下文更长、工具调用更像样。我们能买到越来越聪明的“脑子”。

但模型再强，也有一个绕不过去的事实：

> **它看不见屏幕，也按不下按钮。**

它能替你分析一封邮件，但打不开你的收件箱；能帮你写好一段话，但发不出去；能帮你规划一天的安排，但进不了你的日历。

一个真正能干活的 Agent，需要三样东西：**脑子、眼睛、手。**

现在这三样里，只有脑子被卷到了极致。这篇文章讲的是怎么把另外两样补齐。

![Tiro 给 Agent 接上眼睛和手](/images/writing/articles/esp32-iphone-experiment/01.webp)

## 一、为什么手机是最难的那一块

在 iPhone 上，想让程序替你操作另一个 App，传统上只有这几条路：

| 路线 | 门槛 | 问题 |
|---|---|---|
| 官方 API | 低 | 只有极少数 App 开放，多半不覆盖核心动作 |
| XCTest / WebDriverAgent | 高 | 需要 Mac、Xcode、开发者账号签名（免费签名 7 天过期） |
| 越狱 / 私有 API | 极高 | 普通用户不可行，风险不可控 |
| 协议逆向 / 外挂 | 中 | 脆弱，对方一改就失效，通常违反用户协议 |

而偏偏，手机里装的是人最真实的一层数字生活：**即时通讯、日程、邮件、支付、出行、审批、笔记。**

于是就有一个有点讽刺的结论：

> **Agent 最想去的地方，恰恰是防守最严密的地方。**

---

## 二、绕开的思路：既然不给接口，那就用屏幕

如果正面进不去，还有没有别的入口？

有，而且这个入口一直都在：

> **所有 App 都未必有 API，但所有 App 一定有界面。**

界面是人机之间唯一 100% 通用的接口。它不是为程序设计的，是为人设计的——但正因为如此，一个“像人一样”的 Agent 就能用。

翻译成工程语言只有两行：

- **输入 = 屏幕像素**（看到什么）
- **输出 = 键鼠事件**（点了哪里、打了什么）

这就是 **GUI Agent**：不要求任何 App 开放接口，不要求系统开后门，只要求一件事——**看得见画面，动得了输入。**

---

## 三、眼睛和手是怎么凑齐的

具体到 iPhone 上，这套东西长这样：

> **眼睛 = AirPlay 屏幕镜像；手 = 一块 ESP32 小板子。**

![图 1 ｜ AirPlay 看屏幕，ESP32-S3 执行键鼠动作](/images/writing/articles/esp32-iphone-experiment/02.webp)

iPhone 上什么都不用装，不用越狱，不用开发者账号，只需要打开一个系统自带的无障碍功能：**辅助触控**。

| 角色 | 负责什么 |
|---|---|
| iPhone | 运行任何 App，把画面发出去，接收鼠标和键盘事件 |
| 电脑 | 接收画面帧、换算坐标、运行 Agent |
| ESP32-S3 | 插在手机 USB 口上，模拟标准鼠标和键盘 |

有一点必须讲清楚：

> **ESP32 上不跑模型，不读任何 App 的数据库，也不调用任何私有 API。**

它只是一个“手”。电脑通过 Wi-Fi 告诉它“往右移 30、点一下、输入这几个字符”，它把这些翻译成 USB 的鼠标键盘事件发给手机。所有判断都在电脑上完成。

所以它也不是后门。外挂是钻进 App 内部偷数据；GUI Agent 是坐在屏幕外面，像人一样操作界面。

---

## 四、它干活的方式：看 — 想 — 动 — 查

这是 GUI Agent 和 Web Agent 最本质的区别。

Web Agent 做完一步，可以读页面结构来断言“这个元素出现了吗”；GUI Agent 什么都没有，它只有一张图。

所以它的循环里必须有最后一步：**查**。

![图 2 ｜ 看、想、动、查：确认后再继续](/images/writing/articles/esp32-iphone-experiment/03.webp)

- 点完一个按钮，要确认界面真的变了；
- 发完一条内容，要确认它真的出现了；
- 没变？就停下来重新看，而不是再点一次。

在这个范式里，**验证不是性能优化，而是它能不能成立的前提。**

---

## 五、连上之后，iPhone 上它都能做什么

一句话回答：

> **人在屏幕上用手指能完成的事，它都能做。**

![图 3 ｜ 同一块屏幕，连接消息、日程、邮件和待办](/images/writing/articles/esp32-iphone-experiment/04.webp)

它不是某个 App 的插件，接管的是更底层的一层东西——**人机交互层**。这层是所有 App 共用的：日程、邮件、待办、社交、内容、出行、审批，全都长在同一块屏幕上。

开头那段视频里的“回一条微信消息”，只是这张图上的一格。

## 六、真正难的地方

听起来很顺，坑其实都在细节里：

**1. 指针会漂。** USB 鼠标是相对位移，不是绝对坐标，iOS 还有指针加速。所以每次点击前，都要重新在画面里定位一次指针，不能“算出来在哪就直接点”。

**2. 只有像素，没有权威状态。** 模型看截图会看错，动画会造成误判。所以“点了没生效”是常态，必须靠验证兜底。

**3. 中文打不进去。** 标准 USB 键盘协议只支持 ASCII。现实的做法是走手机自己的拼音输入法：打拼音、看候选区、选词、逐字核对，再发送。所以“输入”和“发送”必须拆成两步。

**4. 慢，而且不可回滚。** 一次 API 调用是毫秒级，一个 GUI 原子动作是秒级；而消息发出去撤不回、钱转出去退不回，所以动作失败时绝对不能盲目重放。

**5. 有些界面它根本看不到。** 密码输入、支付确认、受版权保护的视频不参与屏幕镜像。Agent 在这里是彻底瞎的——这其实是好事，等于系统替你划了一条安全线。

---

## 写在最后

它现在还需要一台电脑当大脑，识图会错、指针会漂，离“无人值守”还很远。

但这条路的意义在于：**它不需要任何 App 点头。**

聪明的模型我们已经有了。接下来拼的，是谁先给它安上眼睛和手。

当所有 App 都拒绝开放接口时——

**屏幕，是 AI 唯一通用的那一个。**
