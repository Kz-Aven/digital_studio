> 企业 Agent 治理系列：像办理新员工入职一样，设计可信身份。

工厂新来一位计划员，你会直接把生产系统的管理员账号交给他吗？

通常不会。先登记资料、确定岗位和负责人，再开账号、分权限，之后才安排工作。

Agent 进入企业，也应该走完这条“入职流程”。

所谓可信身份，就是让系统能确认：**它是谁、归谁负责、这次凭什么做事，做完能否查清。**

## 一、建档发工牌：先把“谁”说清楚

创建 Agent 角色，像填入职资料、发工牌。但岗位名称还不够，“生产计划助理”可以有好几个。

产品需要为每个实际使用的 Agent 建立独立档案：唯一编号、所属工厂、工作职责、业务负责人、当前状态。

名字可以改，编号要保持稳定，历史记录才能找得到同一个执行者。两个工厂使用同一份助理模板，也应分别建档、分别授权。

用户打开详情页，应该能看懂：“这是二厂的交期协调助手，计划部负责，目前已启用。”

![一人一档，工牌与身份记录对应](/images/writing/articles/agent-identity/01.webp)

还要注意：**工牌上写了谁，不等于来刷卡的就是谁。**系统调用业务工具时，要通过受控的身份凭证确认执行者，不能因为请求里写着“我是生产主管”就相信它。

## 二、开通账号：岗位、能力和权限分别安排

新人懂采购流程，不代表能付款。Agent 会查库存、会写排产方案，也不代表有权修改生产计划。

给它“入职”时，可以在配置页说清三件事：

| 配置什么 | 交期协调助手的例子 |
|---|---|
| 能力 | 查订单、分析缺料、生成方案 |
| 数据范围 | 仅授权工厂与客户的必要数据 |
| 操作权限 | 可起草申请；正式变更须审批；禁止直接付款 |

这些权限应衔接企业已有的账号与审批制度。不要为了接入方便，所有 Agent 共用一个管理员账号，否则既难隔离权限，也难追溯操作。

凭证由系统管理，不让员工把账号密码直接贴进聊天窗口。

## 三、派工单：这次代表谁，干到哪里

岗位权限是长期安排，派工单限定这次工作。

假设销售对 Agent 说：“帮我评估订单 A 能不能提前两天交货。”

这次任务应记录销售是发起人，交期助手是执行者，只处理订单 A；先交付可行方案，不自动对客户承诺。

任务页可以这样显示：

> **本次任务：评估订单 A 的交期**\
> 自动完成：查授权数据、起草方案。\
> 需要审批：修改交期、发送正式承诺。\
> 授权到期或被撤销后，不再继续执行。

已有权限覆盖的动作，Agent 可以连续完成，用户不必守着屏幕。遇到需要审批的节点，再通知有权负责人。

![派工单限定本次对象与动作](/images/writing/articles/agent-identity/02.webp)

**销售没有排产权，不能因为说了“你直接办”，就借 Agent 获得排产权。**任务转交给另一个 Agent，也不等于权限一起转过去。

## 四、刷卡办事：每次操作都验身份和授权

员工拿着工牌，也不能进入所有车间。Agent 发起实际操作时，系统同样要检查：身份是否仍有效、对象是否在范围内、动作是否被允许。

如果要改交期，还要核对审批是否对应当前方案，以及业务条件是否仍成立。批准订单 A 的方案，不能拿去修改订单 B。

允许就执行；缺审批就等待；信息不足就转交；明确禁止就拒绝。

这道检查应放在业务系统的操作入口，不能只在提示词里写一句“请遵守规定”。

## 五、工作档案：记录发生过什么，也说明没看到什么

我落地过的项目里，会把 Agent 的任务原文、最终回复、可采集的工具活动、错误和耗时整理成工作档案，并关联当时的助理与能力配置。

不同平台和助理的档案分开保存，查询时能定位具体执行记录，避免同名助理的工作混在一起。查询接口只提供读取能力，记录中的凭据类敏感信息会先做脱敏处理。

还有一个很实用的设计：明确标出采集覆盖是否完整、已采集内容是否完整保存。只拿到部分过程，就如实标注，不能假装看到了全部。

![工作档案如实标注缺失，不能补造证据](/images/writing/articles/agent-identity/03.webp)

放到工厂，这能帮助负责人复盘：是谁处理的订单、用了什么工具、哪里出错。

若要进一步追溯“谁发起、谁批准、凭什么执行”，还要把身份和审批系统的记录关联进来。**有执行日志，不等于已经拥有完整授权证据。**

## 六、调岗和离职：权限要能收回来

员工调岗、离职，要交接工作、回收账号。Agent 更换负责人、暂停或停用时，也需要对应入口。

管理员应能撤销授权、停用凭证，说明未完成任务交给谁；后续操作重新校验，不能继续沿用旧权限。

已经生效的订单变更，需要另走纠正流程；历史工作档案按企业的留存与访问规则保存，不能因为助理被删除，就把证据一并清掉。

![停用权限，保留历史工作档案](/images/writing/articles/agent-identity/04.webp)

给 Agent 发工牌只是开始。把建档、开账号、派工、操作核验、工作留痕和权限回收连起来，企业才知道交出去的每一项工作，由谁负责、受到什么约束。

你准备让 Agent 上岗时，这几道“入职手续”办齐了吗？
